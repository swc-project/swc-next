# @swc-next/types

Shared ESTree declarations for SWC Next's parser, decoder, encoder, and codegen.

```ts
import type { Program, Node } from "@swc-next/types";
```

The declarations are generated by `cargo run -p ast_tools` from the Rust AST and
its `#[estree(...)]` annotations. Public types intentionally allow ESTree input
from other tools: positions and extension fields can be absent, and identifiers
and literals use common interfaces. A successful type check does not validate
an arbitrary AST at runtime.

Annotations on AST definitions describe the JavaScript projection without
changing Rust fields or the binary layout. Rust `Option<T>` fields accept both
absence and `null` in the public declarations:

- `ts_alias = "..."`: represent a Rust node or container using another TS type.
- `ts_type = "..."`: override a node's `type` discriminator or a field's type.
- `add_fields(body = Null, expression = False)`: describe synthetic JS fields.
- `add_ts_def = "..."`: supply a shared or contextual public declaration.
- Enum `add_ts_variants = "..."`: include variants allowed by external declarations.
- Field `ts_skip`, `ts_rename = "..."`, and `ts_optional`: describe fields which
  are transformed, renamed, or may be absent in compatible input.

Existing ESTree node names, conditional fields, and enum values are shared with
the decoder generator. Shape-changing runtime conversions remain in the codec
generators; update their annotations together when changing a conversion.
